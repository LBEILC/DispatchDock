# 需求与范围

## 1. 定位

一个 agent（派活方）把能写清楚要求的工作派给另一个 agent（干活方）在后台执行，人在旁边统一查看、停止和验收。和"人同时开几个 agent 并排看"的工具不同：**派活的是 agent，人只看和拍板**。

配套开源两部分：

- **技能**：单独就能用（终端只读窗口看进度）。
- **监控软件**：装了以后体验更好（统一列表、结构化时间线、通知、配置界面、一键安装技能）。软件没开时，技能自动退回终端窗口。

两部分之间只有本机文件协议（`docs/protocol.md`），不开网络端口。

## 2. v0.1 范围

| 方向 | v0.1 支持 |
|---|---|
| 派活方（宿主） | Claude Code（含 Claude 桌面端的 Code 页）、Devin |
| 干活方 | Codex CLI |
| 平台 | Windows 10/11（实现上不写死 Windows） |

### 2.1 技能

- `codex-dispatch`：派活、看进度、收汇报，不带角色。派发脚本分成**公共部分**和**干活方适配器**；v0.1 只实现 Codex 适配器，同时写一份"新增适配器"的说明作为模板。
- `dual-role-workflow`：保持现在的立场，设计负责人（派活方的模型）做决策和审美，Codex 做执行。
- 两个宿主之间只有少量差异（怎么后台运行、怎么等待结束、工具名大小写、宿主名称）：正文只写一份，差异放在 `skills/_hosts/<宿主>/`，由安装器合成。
- 去掉个人化内容：写死的用户路径、个人默认模型和档位、"用户额度充足"一类的话。

### 2.2 配置

- 共享配置文件 `config.json`（位置见协议），内容有：干活方默认的模型、推理强度、档位、沙箱，进度窗口策略。
- 优先级：命令行参数 / 环境变量 > `config.json` > 内置默认。**内置默认不覆盖干活方自己的配置**：例如模型没配置时不传 `-m`，由 Codex 自己的 `config.toml` 决定。
- 监控软件提供配置界面；没装软件的人可以手写 `config.json`，或者继续用环境变量。
- 单次任务的参数（例如调研任务用只读沙箱）仍由派活方在派发时决定，配置只管默认值。
- 托管开关也在 `config.json` 里（见 2.5），技能正文不写开关。

#### 首次配置

第一次装好以后，让用户自己定默认值，装不装软件都要有办法：

- **装了软件**：首次打开时有一步引导，检测 Codex，填默认模型、强度、档位、沙箱、窗口策略、是否托管，写入 `config.json`。之后在设置页改。
- **只装技能**：安装命令在首次安装时逐项询问（每项都可以直接回车，表示"跟随 Codex 自己的配置"）。派发脚本另有一个查看和修改配置的子命令。
- **都没做也能用**：没有 `config.json` 时全部跟随 Codex 自己的配置，进度里提示一行怎么设置。技能正文告诉派活方：看到这行提示，任务结束后问用户一次要不要设置默认值，不每次都问。

### 2.3 监控软件

**界面方向**：设计令牌、组件库、整体视觉沿用现有的查看器，大方向保持一致。任务监控相关的交互重新设计，需要时写新的自定义组件。界面稿由设计负责人先出，放在 `app/design/`。

- 功能上覆盖现有查看器"任务"页已有的：列表、筛选、结构化时间线、汇报渲染、停止、完成通知、导入旧任务、接管终端窗口。
- 只读统一事件（协议里的 `events.jsonl`），不认识任何一家干活方的原始格式。例外：没有 `events.jsonl` 的旧任务，读 `progress.log` 作为兼容路径。
- **宿主检测与技能安装**：检测本机装了哪些派活方（Claude Code 的 `~/.claude/skills`、Devin 的 `%APPDATA%\devin\skills`），一键安装或更新技能，显示各宿主已装版本。安装前备份，可回退。
- **干活方检测**：Codex CLI 是否装了、版本号、能否运行。版本和上次不同时提示"事件格式可能有变化"。
- 配置界面和首次配置引导（2.2）。

### 2.4 公开版技能

仓库里的 `skills/` 是公开版：通用、没有个人内容。用户自己改过或手装的技能，安装器默认不替换（协议第 8 节）。

### 2.5 托管模式（开关）

问题：任务进程是派活方会话的子进程，关掉 Claude Code 或结束会话可能连带中断任务。在派活方内部让进程脱离父进程，试过几种办法都不可靠。

做法：**由监控软件启动任务**。软件不在派活方的进程树里，会话关掉也不会连带结束任务。

- 开关是 `config.json` 的 `managed`，默认关；在软件设置页和首次引导里切换。技能正文不用改派发命令。
- 开关打开、并且软件正在运行时，派发脚本把任务交给软件，自己留下来跟随进度、在任务结束时用同样的退出码退出。所以派活方"后台运行、结束时收到通知"的用法不变。
- 派活方的会话或等待进程被关掉时，任务继续跑；用户在软件里看到它，照样停止和验收。
- 软件没开、或者没在几秒内接手时，派发脚本自己运行（和现在一样），进度里记一行原因。所以打开开关不会让派发失败。
- 只装技能、没装软件时，这个开关没有作用。
- 文件协议见 `docs/protocol.md` 第 7 节（草案，实现时实测后定稿）。

### 2.7 不做
